# AgentLintel Trademark Policy

This policy covers names, logos, badges, and compatibility language associated
with AgentLintel. It is a practical repository policy, not legal advice.

## Reserved Marks

The project owner reserves rights in the following marks:

- AgentLintel
- AgentLintel Context
- AgentLintel Slices
- AgentLintel Core
- AgentLintel Compatible
- AgentLintel Verified
- AgentLintel Certified
- any AgentLintel logo, badge, seal, or certification mark

## Permitted Descriptive Use

You may use the AgentLintel name to describe truthful compatibility or origin,
for example:

- "built with AgentLintel Core";
- "uses the AgentLintel Context schema";
- "compatible with AgentLintel conformance fixtures";
- "forked from AgentLintel".

Do not imply sponsorship, endorsement, certification, or official status unless
you have written permission from the project owner.

## Restricted Use

You may not use AgentLintel marks in a way that suggests your product, service,
plugin, pack, verifier, benchmark, or hosted offering is official, certified, or
endorsed by AgentLintel without written permission.

Restricted examples include:

- selling, reselling, or offering as a service the software or any fork of it
  under the AgentLintel name or a confusingly similar name;
- naming a competing product "AgentLintel Enterprise";
- publishing an "AgentLintel Verified" badge without approval;
- using AgentLintel logos in a commercial service header;
- registering confusingly similar package, domain, or marketplace names
  (including npm packages under or imitating the `@agentlintel` scope);
- claiming official compatibility without passing an approved compatibility
  process.

## Relationship To The Code Licenses

Trademark rights are separate from the code licenses and are not granted by
them. This includes versions whose Functional Source License term has
converted to Apache-2.0 under the future grant: the code becomes open source,
the marks do not. Distribute modified or commercial derivatives under your
own name.

## Forks and Modified Versions

Forks should clearly identify themselves as forks or modified versions. If a
modified version changes behavior, rules, verification output, schemas, or
commercial terms, it should not present itself as the official AgentLintel
project.

## Compatibility Claims

Compatibility claims should be specific and evidence-based. Prefer statements
such as "passes the public `slice.no-deep-imports` conformance fixtures" over
generic claims such as "AgentLintel certified".
